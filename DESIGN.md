# Design System: Deckmate

The code is the source of truth. If this document differs from the implementation, follow the code.

## Overview

**Creative North Star: "Agent Ready Work"**

Deckmate is a local service for managing work through typed decks, cards, and cross-deck tracks, with Markdown storage and direct agent access.

The dark theme is the default (`client/styles.css`, `:root.dark`). Use a 1700×1000 viewport for layout comparisons. The light theme is available through a switch and must remain functional: use tokens, not hardcoded colors. People and agents are equal team members; connected projects do not define the service's identity.

Catalog hierarchy: project → independent spaces → typed decks → cards. A deck is not a mechanic file, and a space is not inferred from a folder or group. A cross-deck track connects cards from different decks; a card can belong to several tracks. Card content and the relationship catalog stay in Markdown; SQLite is an index. The editor keeps Markdown structure easy to read and edit.

**Key Characteristics:**

- Spaces, decks, and tracks are explicit catalog entities, independent of files.
- Asset, Task, Knowledge, and Mixed decks allow different card types; the server and UI share one type policy.
- Task shows a state, Hero shows subcards and progress, and Doc shows a document without a task state.
- Track progress counts unique Task.id values; the total card count is shown separately.
- Search, relationships, and previews use real data; the inspector exposes the Markdown source.
- Space presets are GDD, Tasks, Knowledge, QA, and Custom; the preset sets the default type for new decks.
- Task decks open in Table; Asset decks open in Cards. The initial grouping is Priority; Ordering controls grouping and sorting in both views.
- Summary, Filters, Ordering, Activity, CardPreview, and New Card share one left column, 420–800px wide.
- Journey creates real Sub Cards from selected steps; automatic pipeline execution is not supported.
- Owner comes from the configured team roster: Agents and Humans; legacy annotations are shown separately.
- Checkboxes and Shift select visible cards; a green selection toolbar replaces the header in the same sticky slot.
- Edit Card, New Card, Journey steps, and focus mode share CardEditForm: monospaced text, title on the first line, menus for “/”, “$”, “#”, and “@”; Ctrl+Enter saves.
- Content and Properties replace each other within one card; dragging Sub Card rows changes their order and saves it in Markdown.
- Card faces are matte; sheen stays within the metallic bottom band. Dragging a deck uses the whole tile and rearranges the row immediately.

## Colors

Selects (2026-11-10): native single-select controls retain their local button styling and share a muted chevron that turns on opening. Their surface-colored popup has a line border, shadow, rounded corners and a thin themed scrollbar; options highlight on hover or keyboard focus and use a focus-colored checkmark. The popup enters with the quick overlay spring, disabled for reduced motion.

Dark theme tokens are defined in `:root.dark` (`client/styles.css`). The light theme uses the base `:root`, is enabled with a switch, and uses the same roles. Use the existing tokens (`--chrome`, `--tab-*`, `--mint*`, `--gold-*`, `--kind-*`, `--count-*`, `--cover-window`) from the code rather than creating duplicates.

### Primary

- Surfaces: canvas #322f40 for the page and active tab; ground #27242f for the catalog background, card groups, and lightweight panels; surface #39354a for fields, controls, and table rows; sidebar #1c1a24 for the open deck header and cover image window; chrome #27242f for the top bar.
- Text and lines: ink #edeef2, muted #cdc8dc, line #4a4560, hover #443f59.
- Actions: accent #c3a3e5 for links and action ink; accent-soft #453351 for quiet emphasis; primary buttons use violet-fill #68478c and violet-fill-ink #f5effc, so the light accent is never mistaken for a dark filled surface. Focus #cfb4ec draws a keyboard-only 2px outline 2px off the edge (Vision keeps it inset inside the clipped canvas); danger #edaaa9 is text, while danger-fill #983c56 with white ink confirms a destructive action. Warnings use warning-bg #4a3a22 and warning-ink #fde793.
- Light surfaces (2026-11-11): canvas #f0ecf4, ground #ebe5f0, surface #f3f0f6 and sidebar #e1d9e8 keep the working area tinted. Ink #2f2440 and muted #51445f remain readable on every base surface. Line #afa1bd is a decorative separator; field-line #85718f is the stronger input boundary. Accent/violet-fill #68428b, accent-soft #e4d8ef, hover #dcd2e6, focus #6e4697 and danger #983c56 encode actions and states. Editor background is #efebf4, with muted hints. Plum #8a6aa6 colors the page light; dark plum is #906cbd.
- Tabs: inactive tabs use tab-idle #6e6884 with white count-face text; the active tab uses the page color (canvas) with tab-ink #e2dcee text.

**The Clear Active State Rule.** Active controls use a `--mark` line and label over `--mark-tint`; keyboard focus uses a #cfb4ec outline in dark. Status includes a text label and does not replace selection feedback.

### Mint, gold and card material

- Mint actions use `--action-mint-ink`: #0c5547 in light, #a8eedf in dark, on a transparent face. `--mint` #a8eedf remains a fill and must not be used as light-theme text. The current Sub Cards row carries the `--tile-highlight` ring.
- The logo is a purple card with a gold diamond pip: mark-back, mark-front, and mark-pip, with a separate light-theme set. tools/render-logo.mjs renders the files in assets/logo.
- Hero uses warm light gold (2026-11-08): hero-metal #e8bd48 (light theme #edc451), near-black hero-ink #24180a numerals, and pale-yellow hero-sheen #fff4c2 reflections. Table row and family panel bands use hero-strip; chips and progress use hero-chip #f4e4b8, but light-theme Table chip text uses hero-ink in normal, checked and opened rows; the Hero tile's Sub Card progress (2026-11-09) is a quiet 3px line of light on the gold, the same in both themes: hero-step-done for accepted steps, hero-step-working, a faint violet hero-step-review and rose hero-step-blocked, and hero-step-empty for the rest. Each step is as long as its Sub Card's effort (unestimated work weighs one point, as in the tile's effort total) over a 3px floor; a finished family closes into one unbroken line. The Sub Cards panel keeps the full state colors. gold-chip #fde793 with gold-chip-ink #8a5300 (2026-11-08; 5.13:1, light theme: the same face with warning-ink #80531c) is for card links and the Hand due-soon count, not Hero cards.
- Light-theme cards use a #f8f6fa face, #b5a9c4 border, #2a2440 text, #514a66 muted text, and a #cdc8dc Task band; tile metrics use metal-shadow #241b24 ink.
- Dark cards use card-face #322f40, card-ink #f9f9fa, card-muted #cdc8dc, and card-edge #4a4560; shadows are card-shadow 0 2px 6px #0c0a1355 and card-hover-shadow 0 6px 16px #0c0a1377 (light theme: 0 5px 12px #18213624 and 0 9px 20px #18213638).
- Type bands (2026-11-08): Hero uses hero-metal, Doc uses copper doc-metal #e0ac86 with doc-ink #2e1606 (2026-11-09, in both themes, the open card's band included), Task uses card-metal #c6bee3 (light #cdc8dc), and accepted Task uses accepted-metal #34a865 with accepted-metal-ink #102016 text in both themes. Shared band text uses card-metal-ink #2b2540 (light #40465a); Hero uses hero-ink. Dark accepted ink replaces white to keep small text above 4.5:1 across the satin.
- Satin at rest (2026-11-08): Deck, CardPreview, New Card, Hand, Board, Journey footers and Sub Card affiliation strips share `client/card-material.css`. A broad 112deg gradient uses low/base/high/base/base stops at 0/22/48/76/100%; low mixes 90% metal with metal-shadow #241b24, high adds 24% hero-sheen on gold or 16% metal-sheen #fff8e8 on other metals. ### Controls

**The Foil Rule (2026-11-10).** Rounded hairline controls and lit glass panels can read as cheap capsules, and very dark surfaces can obscure the card preview's edge. Deckmate is an Operate tool, so its controls stay familiar and precise and give the depth to cards. Every interactive control is drawn one way, from `client/surface.css`:

- **Shape.** A 2px rectangle (`--control-radius`) for buttons, toggles, chips, segmented controls, rail buttons, fields and the closed part of selects. One deliberate exception: the server status badge in the top bar («Live», where every save shows) stays a capsule.
- **Edge.** A `.67px` hairline (`--control-hairline`, one device pixel at 150%) in `--control-line` — `--button-line` mixed 62% into the page ground, quiet at rest; hover brings the full `--button-line`. Use one border or rim on a boundary; focus is a separate state.
- **Label.** Source Sans 3 500 with .01em tracking: shared tools and Buttons use 13/18; reading actions use 14/20, local 24px compact controls use 12px; the primary action is 600; numbers inside are Geist Mono. Shared `.control` and small/default Buttons wrap long labels and grow vertically within their container; glyphs do not shrink. No 700 on controls.
- **Sizes.** Desktop targets are 24px compact, 30px tools, 32px rails and 36px default Buttons. Glyphs retain their own 16px row or 20px rail size. Groups reserve the targets and an 8px gap in layout, except contiguous segmented choices; dense local toolbars wrap complete groups or put secondary actions in their menu. Local size overrides must retain the minimum, and fixed tracks must reserve it; hit areas must not overlap neighbouring controls or cards.
- **Tile band targets.** The tile band is 24px high (29px on a Hero), too low for a 44px target. - **Variants.** Outline (`.control`, `Button variant="outline"`): transparent, the quiet hairline, `--button-ink` — the secondary button and the off state of every toggle and chip. Ghost (`.control.control-ghost`, `variant="ghost"`): no visible edge, a muted icon — icon buttons in heads and footers. ### Tracks and search

Tracks are many-to-many relationships; each track shows the total card count separately from N of M unique accepted Task.id values. Catalog search covers decks and spaces; card search covers the current scope's titles, Markdown, paths, and owners. Source, scope, deck, track, card, q, kind, state, owner, layout, Ordering, and Sub Cards mode persist in the URL. Cards use `/r/c-<alias>?source=...`; Journeys use `/r/p-<alias>?source=...`.

### Selection

A checkbox does not open a card; when selection is active, a click toggles selection, otherwise it opens the preview. Shift selects a range in visual order; Select All selects only visible cards. Changing filters keeps the intersection with visible cards; changing source, scope, or track clears selection. Escape clears selection; if a menu is open, it closes the menu first. Copy refs generates actual short links; Move to Deck offers compatible decks; Add to Track adds a relationship. Writes are sandbox-only, up to 1000 cards per operation.

## Do's and Don'ts

### Do:

- Do keep the dark theme as the default, using `:root.dark` tokens; add new colors as tokens, not hardcoded values.
- Do keep the light theme functional with tokens, not hardcoded colors.
- Do preserve Source Sans 3, Geist Mono, Roboto Mono, and the specified dimensions: 146.67×200 gallery cover, 165×225 shelf face and 132×180 settings preview, 115×147 card, resizable 420–800px sheet, 379px Sub Card column, and 7 Hand slots.
- Do distinguish covers, Task, Hero, and Doc; calculate counters and progress from real data.
- Do preserve input during WS refresh and conflicts, keyboard focus, safe Markdown, and reduced motion.
- Do verify layout measurements (`npm run capture`) alongside reference images.

### Don't:

- Don't switch the default to the light theme or restore the old gallery dimensions (175×235, 165×225, 132×172) without an approved design change.
- Don't substitute visual review for technical checks or carry results from old builds over to new ones.
- Don't restore “deck = mechanic” or “space = folder/group” assumptions.
- Don't treat the SQLite index as the source of card text.
- Don't promise automatic type conversion, pipeline execution, or Journey features beyond the contract.
- Don't apply card glow to every control or make card faces glossy.
- Don't give a button, toggle, tab or chip a glass face, a gradient, a capsule shape or a filled chosen state, or show a focus ring after a click or a tap: controls follow the Foil Rule.
- Don't put a shelf plank under the covers, mirror them, give them a spine crease or other book or box detail, make them holographic, tilt, raise or grow them or their art on hover, make them glow, light them where the pointer is, dim the other covers, or put a dark seam or shade under the art: the Decks home keeps glass covers, flat panels, foil and soft page light, kept easy to read.
