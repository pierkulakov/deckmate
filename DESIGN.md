# Design System: Deckmate

The code is the source of truth. If this document differs from the implementation, follow the code.

## Overview

**Creative North Star: "Agent Ready Work"**

Deckmate is a local service for managing work through typed decks, cards, and cross-deck tracks, with Markdown storage and direct agent access.

The dark theme is the default (`client/styles.css`, `:root.dark`). Use a 1700×1000 viewport for layout comparisons. The light theme is available through a switch and must remain functional: use tokens, not hardcoded colors. People and agents are equal team members; connected projects do not define the service's identity.

Catalog hierarchy: project → independent spaces → typed decks → cards. A deck is not a mechanic file, and a space is not inferred from a folder or group. A cross-deck track connects cards from different decks; a card can belong to several tracks. Card content and the relationship catalog stay in Markdown; SQLite is an index. The editor keeps Markdown structure easy to read and edit.

**Key Characteristics:**

- Spaces, decks, and tracks are explicit catalog entities, independent of files.
- Asset, Task, Knowledge, and Mixed decks allow different card types; the server and UI share one type policy.
- Task shows a state, Hero shows subcards and progress, and Doc shows a document without a task state.
- Track progress counts unique Task.id values; the total card count is shown separately.
- Search, relationships, and previews use real data; the inspector exposes the Markdown source.
- Space presets are GDD, Tasks, Knowledge, QA, and Custom; the preset sets the default type for new decks.
- Task decks open in Table; Asset decks open in Cards. The initial grouping is Priority; Ordering controls grouping and sorting in both views.
- Summary, Filters, Ordering, Activity, CardPreview, and New Card share one left column, 320–800px wide.
- Journey creates real Sub Cards from selected steps; automatic pipeline execution is not supported.
- Owner comes from the configured team roster: Agents and Humans; legacy annotations are shown separately.
- Checkboxes and Shift select visible cards; a green selection toolbar replaces the header in the same sticky slot.
- Edit Card, New Card, Journey steps, and focus mode share CardEditForm: monospaced text, title on the first line, menus for “/”, “$”, “#”, and “@”; Ctrl+Enter saves.
- Content and Properties replace each other within one card; dragging Sub Card rows changes their order and saves it in Markdown.
- Card faces are matte; sheen stays within the metallic bottom band. Dragging a deck uses the whole tile and rearranges the row immediately.

## Colors

Dark theme tokens are defined in `:root.dark` (`client/styles.css`). The light theme uses the base `:root`, is enabled with a switch, and uses the same roles. ### Primary

- Surfaces: canvas #322f40 for the page and active tab; ground #27242f for the catalog background, card groups, and lightweight panels; surface #39354a for fields, controls, and table rows; sidebar #1c1a24 for the open deck header and cover image window; chrome #27242f for the top bar.
- Text and lines: ink #edeef2, muted #cdc8dc, line #4a4560, hover #443f59.
- Actions: accent #9258e5 for active navigation and primary buttons (hover #d4b4ff); accent-soft #442b5d for the summary description background; focus #b79cf2 for a 2px outline with a 3px offset (2026-11-08: Vision keeps this outline inset inside the clipped canvas); danger #ff8a80; warnings use warning-bg #4a3a22 and warning-ink #fde793.
- Tabs: inactive tabs use tab-idle #6e6884 with tab-idle-ink #27242f text; the active tab uses the page color (canvas) with tab-ink #e2dcee text.

**The Clear Active State Rule.** Active controls in the dark theme use accent #9258e5 with light surface text; focus uses a #b79cf2 outline. The light theme uses #7443a6 and #fdfaff. Status includes a text label and does not replace selection feedback.

### Mint, gold and card material

- mint #a8eedf is the Journey button color (mint-ink #0c5547 text, mint-edge #74dcc8 edge); mint-edge highlights the current Sub Cards row with a border, a 2px outline, and a 10px glow.
- The logo is a purple card with a gold diamond pip: mark-back, mark-front, and mark-pip, with a separate light-theme set. tools/render-logo.mjs renders the files in assets/logo.
- Hero uses warm light gold (2026-11-08): hero-metal #e8bd48 (light theme #edc451), near-black hero-ink #24180a numerals, and pale-yellow hero-sheen #fff4c2 reflections. Table row and family panel bands use hero-strip; chips and progress use hero-chip #f4e4b8, but light-theme Table chip text uses hero-ink in normal, checked and opened rows; empty Sub Card steps use hero-step-empty, darker than the band. gold-chip #fde793 with gold-chip-ink #8a5300 (2026-11-08; 5.13:1, light theme: the same face with warning-ink #80531c) is for card links and the Hand due-soon count, not Hero cards.
- Light-theme cards use a #ffffff face, #cdc8dc border, #2a2440 text, #514a66 muted text, and a #cdc8dc Task band with #40465a icons.
- Dark cards use card-face #322f40, card-ink #f9f9fa, card-muted #cdc8dc, and card-edge #4a4560; shadows are card-shadow 0 2px 6px #0c0a1355 and card-hover-shadow 0 6px 16px #0c0a1377 (light theme: 0 5px 12px #18213624 and 0 9px 20px #18213638).
- Type bands (2026-11-08): Hero uses hero-metal, Doc uses doc-metal #9bd4c7, Task uses card-metal #c6bee3 (light #cdc8dc), and accepted Task uses accepted-metal #34a865 with accepted-metal-ink #102016 text in both themes. Shared band text uses card-metal-ink #2b2540 (light #40465a); Hero uses hero-ink. Dark accepted ink replaces white to keep small text above 4.5:1 across the satin.
- Satin at rest (2026-11-08): Deck, CardPreview, New Card, Hand, Board, Journey footers and Sub Card affiliation strips share `client/card-material.css`. A broad 112deg gradient uses low/base/high/base/base stops at 0/22/48/76/100%; low mixes 90% metal with metal-shadow #241b24, high adds 24% hero-sheen on gold or 16% metal-sheen #fff8e8 on other metals. Fine 3% sheen hairlines at 178deg every 2px suggest brushing, without narrow bright stripes or idle animation. The card-to-metal seam has no light bevel: a metal-tinted border (6% shadow) and a soft inset `0 1px 2px` shadow (12%) sit above a 22% shadow bottom edge. Text contrast at the darkest gradient stop: Hero and affiliation 8.15:1 dark / 8.68:1 light; Task 6.91 / 4.80; Doc 7.33 / 4.71; accepted 4.77 in both themes (edges sit outside text).
- Sub Card affiliation (2026-11-08): use the Hero's gold satin, tag emoji/icon and hero-ink name, 600 weight with zero tracking. Deck tiles use 9.5/14px in an 18px strip, 7px left / 2px right padding; selectable tiles reserve 14px at the left in every state, clearing the corner checkbox without shifting the name. This fits Moonwake Lantern even at the standard 115px width and typical names around 20 characters at 132–200px; unusually long names retain the overflow fallback. Sprint/Hand strips use 10/14px; previews use 12/16px in a 30px minimum strip. The Sub Card title remains dominant.
- Selection (2026-11-08): tile-highlight #63e6cf gives hover/focus a 1px #63e6cf70 ring and a 12px #63e6cf30 glow; keyboard focus on the card opener also has a separate 2px focus outline with a 3px offset. The opened card uses a 2px #63e6cfd9 ring and an 18px #63e6cf60 glow. Checked deck cards press down 3px without scaling, tint the face with 18% check-on-face, and use only an inset `0 4px 8px -3px #0c0a1380` shadow. A 2px check-on-edge frame follows the card edge over the band, owner medallion and gold affiliation strip; the band is dimmed with `saturate(.85) brightness(.92)`. Hover tilt and moving sheen stay off; the press flattens a hover tilt over 420ms `cubic-bezier(.33, 1, .68, 1)` rather than the 220ms pointer-follow ease, so the card and its icons settle instead of jumping. An opened checked card retains its outer opened ring and glow; keyboard focus keeps its separate outline, and reduced motion makes the press immediate. Checked table rows use 22% check-on-face over card-face; adjacent rows merge with matching separators into one recessed block, with an inset `0 4px 5px -4px #0c0a1399` shadow only at the top and the normal separator at the bottom. The state strip and opened-row ring retain their meaning.

### Covers, counters and statuses

- Cast covers use a 165deg Deck color gradient, a lit inset rim (`--cover-rim`) and a soft theme-dependent lift (`--cover-lift`). The image window uses cover-window #1c1a24; its 17px type badges use white icons on a dark translucent face. The counter chip uses count-face #ffffff on a count-foot #e2dcee base with count-ink #4c5060 text; the green accepted counter uses accepted-metal. The 3px progress lip uses `--cover-progress` and counts only Tasks.
- Interactive covers highlight with a separate light layer: a pale inner rim, a 1px mint contour, and two soft halo scales (8px near the edge, 24px feathered below it). It fades over 150ms ease-out, stays lit when reaching the settings button, and shares the opening transition. The current deck on the shelf keeps a 2px contour. Keyboard focus replaces the decorative contour with a separated 2px outline of the same mint material; the clipped shelf uses an inset outline in the cover's contrast-checked ink. The face stays matte and still; dragging and reduced motion suppress the light animation.
- `coverStyle` (client/components/Deck.tsx) selects light or dark title text against the band, which shows the Deck color (`--deck-band`). If 4.5:1 contrast is unreachable, it darkens only the band while preserving the hue, the frame and the image.
- Dark theme statuses: planned #a3a9b5, discuss #c9b6d7, iteration #a8b8cf, working #d8bd8d, review #d7a3a0, and accepted #a7c0ad, on ground. Light theme statuses have separate colors and backgrounds (frontmatter, `status-*`).
- Values outside the tokens in `.dark` rules: hover edge #505967, pressed #8e879b, disabled #9299a7 on #262b35.

### Neutral

In the dark theme, panel gradients become solid colors: --panel-gradient = surface, --chrome-gradient = chrome, --tab-gradient = canvas. Colored gradients (plum/champagne mixes) remain in the light theme under the same tokens.

## Typography

Source Sans 3 is for text and actions; Geist Mono is for numbers and counters; Roboto Mono is for the card editing field. Fonts are local, font-synthesis is disabled, and the UI font family uses one token, `--font-sans`.

- Open deck title: 22/700, line-height 28px; project name on the home screen: 16/700.
- Tabs: 15/700. Compact card: 14/500, line-height 17px, at most three lines; the inspector shows the full title.
- Cover: 13/600, line-height 15px, up to two lines. Card sheet: title 24/700, line-height 26.4px; body 14/400, line-height 20.57px.
- Card number on a tile: Geist Mono 14/500; cover counter: Geist Mono 12/500, tabular-nums.
- Table: 12/400, line-height 1.45; column headings 10/500; cell padding 6px 8px.
- Journey: heading 21/500; step instructions in the editor use Geist Mono 12px, line-height 1.65.
- Markdown text in cards and document panels: 14px, line-height 1.72.

**The One Card, One Source Rule.** A Task's number and state connect its views; content is not copied into a deck cover or track. Identify the source by its Markdown path.

## Layout

The shell has one column and a single-row 52px top bar: a 47px project rail, trapezoid tabs, and actions on the right. Tabs are 190×40 with a −14px overlap, `clip-path: polygon(6% 0, 94% 0, 100% 100%, 0 100%)`, and radius 6px 6px 0 0. Inactive tabs use tab-idle; the active tab uses the page color. Tabs and the top bar stay outside the main scroll area; below 1180px the status chip keeps only its dot; below 860px the tabs take their own full-width row under the rail and actions and shrink only when that row is full. Below 480px (2026-11-08), search takes a full-width line above the actions, and the rail sits beside tabs with 8px horizontal insets and untruncated section names. ## Elevation & Depth

- Menus and dialogs: --shadow 0 10px 28px #0c0a1366 (light theme: 0 8px 28px #30243812).
- Cards: card-shadow 0 2px 6px #0c0a1355; hover/focus: 0 6px 16px #0c0a1377. Covers share `--cover-rim` and `--cover-lift`; drag overlay uses `0 14px 28px rgb(0 0 0 / .45)` beneath the rim.
- Mint glow is limited to hover/focus and selected cards; unselected cards do not glow. There are no infinite decorative animations.

**The Depth Belongs to Cards Rule.** Card faces are matte. Sheen stays in the metallic bottom band; a mint ring and local glow indicate hover or an opened preview, while checked cards stay recessed. Unchecked cards tilt up to ±8deg, softer than the ±12deg measured in the author’s reference video, at the author’s request (2026-11-09); deck covers do not tilt because tilt can look like displacement on the home screen. Dragging disables tilt and neighboring hover effects.

Use perspective 850px and requestAnimationFrame; disable tilt on touch and with reduced motion. Tokens: --motion-feedback 150ms, --motion-material 220ms, --ease-out cubic-bezier(.16, 1, .3, 1).

Metal reflection (2026-11-08), after the author’s reference video: tile bands — the Hero footer, the Sub Card affiliation strip, Task and Doc footers — carry one rigid ribbon of metal under their ink (`.card-material-glare`, z-index -1, so numerals, icons and segments stay on top; its own `::after` repeats the band’s inset edge). Along the ribbon: a long ramp from deep amber up to a cream hot edge (sheen 93%), a crisp cut, a second ramp from mid amber to pale gold (sheen 58%), and a crisp cut back to deep amber; the cuts are 0.96 band widths apart and lean 22deg off vertical (90deg gradient on a pseudo-element five band widths long, skewX(-22deg)). Gold deepens with `--metal-amber`, other metal with `--metal-shadow`. At rest the hot cut sits beyond the right edge (`--glare-rest`), so the band reads as plain metal running dark to light with no reflection. The shared `useCardTilt` hook moves the cut through `--glare-shift`, in band widths at the tile’s mid-height: on enter it sweeps in once from the right, while hovered it follows the tilt — `0.377 − 0.522·(x − .5) + 0.485·(y − .5)`, against the pointer horizontally and with it vertically — and on leave it sweeps out to the right; every move is an exponential follow with a 77ms time constant, all fitted to the reference frames. A Sub Card’s strip and footer intersect the same tile-space ribbon: each band’s center `--glare-band-y` offsets X from the tile’s mid-height by `(reference-y - band-y) × tan(22deg)`, using the tile’s inner height and each clipping layer’s container height. Hero gold shows the ribbon at full strength; Task, Doc and accepted metal at .55 over their satin. The open card (CardPreview footer) has no ribbon: per the author’s reference it carries only a soft warm glow — a broad radial light 1.6 band widths across in soft-light blend that spreads over the whole band (opacity .7, 1 while hovered); its center rests a little right of middle and drifts over 700ms through only 30% of the pointer’s travel (35–65% of the band), so the light never gathers under the cursor; it lies in the metal under the ink and controls (z-index -1), so labels keep their contrast and the owner medallion is not lifted below the band edge; the gold parent bar above a Sub Card carries the same light (2026-11-09); it stays visible without drifting under reduced motion. The pointer-events:none clipping layer confines the moving pseudo-element to the band, leaving the protruding owner medallion unclipped. Only transform animates. A tile that can tilt keeps one compositor layer at all times (`will-change: transform` on hover-capable pointers without reduced motion) and the ribbon repaints inside it; nothing switches compositing on hover, because layers created and dropped per hover re-snapped the band’s ink by about a pixel on enter and when the tilt settled (author’s recording, 2026-11-09). The open card’s light keeps its own layer for the same reason. Touch, coarse/no-hover pointers and reduced motion keep the ribbon pinned at rest; checked, disabled and dragged tiles slide back to rest. There is no timed hover pass or idle animation. Accepted Hero foil (2026-11-09, the author’s choice «A++»): an accepted Hero tile keeps its gold band and turns holographic — a rainbow foil in color-dodge over the band, a faint rainbow film on the face (screen in the dark theme, multiply in the light one), a 2px rainbow ring that replaces the border (border-box conic gradient), and glitter gathered around the pointer; segments of its finished bar are accepted green. The rainbow is one long 115deg sweep (`--holo-stripes`, tokens `--holo-rose/-amber/-mint/-sky/-violet`, `--holo-glitter`) shifted by the pointer through `--glare-x/-y/-u/-v` from useCardTilt; `--glare-opacity` lifts it while hovered. Ink stays above the foil. Without hover or with reduced motion it keeps its rest look. Only accepted Heroes carry these blend layers.

Keyboard focus keeps its separate outline. Text inputs and textareas show focus by the caret and their own border colour, without the extra ring (2026-11-09). Pressed buttons move 1px; tab backgrounds transition over 150ms; Content/Properties use 180ms, opacity .5 → 1, and translateX 5px → 0; Overlays use spring curves sampled into linear() in client/motion.css: popovers, menus and tooltips slide 20px out of their anchor (quick spring, 300ms, 6% overshoot); dialogs drop 50px over a fading backdrop (firm spring, 260ms); side sheets slide from their edge and banners open their height (140ms); toasts rise 15px from half size (pop spring, 420ms). After sorting, the card grid's outer layer translates over 220ms from its layout position; new cards use a 150ms opacity transition, and removed cards fade in place over 220ms, beneath the others closing the gap; group headings and Add controls never travel across cards — they fade out where they were and reappear in place once the cards have settled (440ms). Cancel the animation during dragging, scrolling, or width changes. Reduced motion hides the moving reflection, retains the satin and shadowed seam, disables tilt, and shortens other animation/transition to .01ms.

## Do's and Don'ts

### Do:

- Do keep the dark theme as the default, using `:root.dark` tokens; add new colors as tokens, not hardcoded values.
- Do keep the light theme functional with tokens, not hardcoded colors.
- Do preserve Source Sans 3, Geist Mono, Roboto Mono, and the specified dimensions: 132×180 cover, 115×147 card, 456 sheet, 355 subcard panel, and 7 Hand slots.
- Do distinguish covers, Task, Hero, and Doc; calculate counters and progress from real data.
- Do preserve input during WS refresh and conflicts, keyboard focus, safe Markdown, and reduced motion.
- Do verify layout measurements (`npm run capture`) alongside reference images.

### Don't:

- Don't switch the default to the light theme or restore the old dimensions (175×235, 132×172) without an approved design change.
- Don't substitute visual review for technical checks or carry results from old builds over to new ones.
- Don't restore “deck = mechanic” or “space = folder/group” assumptions.
- Don't treat the SQLite index as the source of card text.
- Don't promise automatic type conversion, pipeline execution, or Journey features beyond the contract.
- Don't apply card glow to every control or make card faces glossy.
