# Design System: Deckmate

The code is the source of truth. If this document differs from the implementation, follow the code.

## Overview

**Creative North Star: "Agent Ready Work"**

Deckmate is a local service for managing work through typed decks, cards, and cross-deck tracks, with Markdown storage and direct agent access.

The dark theme is the default (`client/styles.css`, `:root.dark`). Use a 1700×1000 viewport for layout comparisons. The light theme is available through a switch and must remain functional: use tokens, not hardcoded colors. People and agents are equal team members; connected projects do not define the service's identity.

Catalog hierarchy: project → independent spaces → typed decks → cards. A deck is not a mechanic file, and a space is not inferred from a folder or group. A cross-deck track connects cards from different decks; a card can belong to several tracks. Card content and the relationship catalog stay in Markdown; SQLite is an index. The editor keeps Markdown structure easy to read and edit.

**Key Characteristics:**

- Spaces, decks, and tracks are explicit catalog entities, independent of files.
- Asset, Task, Knowledge, and Mixed decks allow different card types; the server and UI share one type policy.
- Task shows a state, Hero shows subcards and progress, and Doc shows a document without a task state.
- Track progress counts unique Task.id values; the total card count is shown separately.
- Search, relationships, and previews use real data; the inspector exposes the Markdown source.
- Space presets are GDD, Tasks, Knowledge, QA, and Custom; the preset sets the default type for new decks.
- Task decks open in Table; Asset decks open in Cards. The initial grouping is Priority; Ordering controls grouping and sorting in both views.
- Summary, Filters, Ordering, Activity, CardPreview, and New Card share one left column, 420–800px wide.
- Journey creates real Sub Cards from selected steps; automatic pipeline execution is not supported.
- Owner comes from the configured team roster: Agents and Humans; legacy annotations are shown separately.
- Checkboxes and Shift select visible cards; a green selection toolbar replaces the header in the same sticky slot.
- Edit Card, New Card, Journey steps, and focus mode share CardEditForm: monospaced text, title on the first line, menus for “/”, “$”, “#”, and “@”; Ctrl+Enter saves.
- Content and Properties replace each other within one card; dragging Sub Card rows changes their order and saves it in Markdown.
- Card faces are matte; sheen stays within the metallic bottom band. Dragging a deck uses the whole tile and rearranges the row immediately.

## Colors

Selects (2026-11-10): native single-select controls retain their local button styling and share a muted chevron that turns on opening. Their surface-colored popup has a line border, shadow, rounded corners and a thin themed scrollbar; options highlight on hover or keyboard focus and use a focus-colored checkmark. The popup enters with the quick overlay spring, disabled for reduced motion.

Dark theme tokens are defined in `:root.dark` (`client/styles.css`). The light theme uses the base `:root`, is enabled with a switch, and uses the same roles. Use the existing tokens (`--chrome`, `--tab-*`, `--mint*`, `--gold-*`, `--kind-*`, `--count-*`, `--cover-window`) from the code rather than creating duplicates.

### Primary

- Surfaces: canvas #322f40 for the page and active tab; ground #27242f for the catalog background, card groups, and lightweight panels; surface #39354a for fields, controls, and table rows; sidebar #1c1a24 for the open deck header and cover image window; chrome #27242f for the top bar.
- Text and lines: ink #edeef2, muted #cdc8dc, line #4a4560, hover #443f59.
- Actions: accent #9258e5 for active navigation and primary buttons (hover #d4b4ff); accent-soft #442b5d for the summary description background; focus #b79cf2 for the keyboard-only 2px outline 2px off the edge (2026-11-10, see Controls; Vision keeps this outline inset inside the clipped canvas); danger #ff8a80; warnings use warning-bg #4a3a22 and warning-ink #fde793.
- Tabs: inactive tabs use tab-idle #6e6884 with tab-idle-ink #27242f text; the active tab uses the page color (canvas) with tab-ink #e2dcee text.

**The Clear Active State Rule.** Active controls use a `--mark` line and label over `--mark-tint`; keyboard focus uses a #b79cf2 outline in dark. Status includes a text label and does not replace selection feedback.

### Mint, gold and card material

- mint #a8eedf marks the Journey button with a mint line and label on a transparent face; mint-edge highlights the current Sub Cards row with a border, a 2px outline, and a 10px glow.
- The logo is a purple card with a gold diamond pip: mark-back, mark-front, and mark-pip, with a separate light-theme set. tools/render-logo.mjs renders the files in assets/logo.
- Hero uses warm light gold (2026-11-08): hero-metal #e8bd48 (light theme #edc451), near-black hero-ink #24180a numerals, and pale-yellow hero-sheen #fff4c2 reflections. Table row and family panel bands use hero-strip; chips and progress use hero-chip #f4e4b8, but light-theme Table chip text uses hero-ink in normal, checked and opened rows; the Hero tile's Sub Card progress (2026-11-09) is a quiet 3px line of light on the gold, the same in both themes: hero-step-done for accepted steps, hero-step-working, a faint violet hero-step-review and rose hero-step-blocked, and hero-step-empty for the rest. Each step is as long as its Sub Card's effort (unestimated work weighs one point, as in the tile's effort total) over a 3px floor; a finished family closes into one unbroken line. The Sub Cards panel keeps the full state colors. gold-chip #fde793 with gold-chip-ink #8a5300 (2026-11-08; 5.13:1, light theme: the same face with warning-ink #80531c) is for card links and the Hand due-soon count, not Hero cards.
- Light-theme cards use a #ffffff face, #cdc8dc border, #2a2440 text, #514a66 muted text, and a #cdc8dc Task band with #40465a icons.
- Dark cards use card-face #322f40, card-ink #f9f9fa, card-muted #cdc8dc, and card-edge #4a4560; shadows are card-shadow 0 2px 6px #0c0a1355 and card-hover-shadow 0 6px 16px #0c0a1377 (light theme: 0 5px 12px #18213624 and 0 9px 20px #18213638).
- Type bands (2026-11-08): Hero uses hero-metal, Doc uses copper doc-metal #e0ac86 with doc-ink #2e1606 (2026-11-09, in both themes, the open card's band included), Task uses card-metal #c6bee3 (light #cdc8dc), and accepted Task uses accepted-metal #34a865 with accepted-metal-ink #102016 text in both themes. Shared band text uses card-metal-ink #2b2540 (light #40465a); Hero uses hero-ink. Dark accepted ink replaces white to keep small text above 4.5:1 across the satin.
- Satin at rest (2026-11-08): Deck, CardPreview, New Card, Hand, Board, Journey footers and Sub Card affiliation strips share `client/card-material.css`. A broad 112deg gradient uses low/base/high/base/base stops at 0/22/48/76/100%; low mixes 90% metal with metal-shadow #241b24, high adds 24% hero-sheen on gold or 16% metal-sheen #fff8e8 on other metals. Fine 3% sheen hairlines at 178deg every 2px suggest brushing, without narrow bright stripes or idle animation. The card-to-metal seam has no light bevel: a metal-tinted border (6% shadow) and a soft inset `0 1px 2px` shadow (12%) sit above a 22% shadow bottom edge. Text contrast at the darkest gradient stop: Hero and affiliation 8.15:1 dark / 8.68:1 light; Task 6.91 / 4.80; Doc 7.09 in both themes; accepted 4.77 in both themes (edges sit outside text).
- Sub Card affiliation (2026-11-08): use the Hero's gold satin, tag emoji/icon and hero-ink name, 600 weight with zero tracking. Deck tiles use 9.5/14px in an 18px strip, 7px left / 2px right padding; selectable tiles reserve 14px at the left in every state, clearing the corner checkbox without shifting the name. This fits Moonwake Lantern even at the standard 115px width and typical names around 20 characters at 132–200px; unusually long names retain the overflow fallback. Sprint/Hand strips use 10/14px; previews use 12/16px in a 30px minimum strip. The Sub Card title remains dominant.
- Selection (2026-11-08): tile-highlight #63e6cf gives hover/focus a 1px #63e6cf70 ring and a 12px #63e6cf30 glow; keyboard focus on the card opener also has a separate 2px focus outline with a 3px offset. The opened card uses a 2px #63e6cfd9 ring and an 18px #63e6cf60 glow. Checked deck cards press down 3px without scaling, tint the face with 18% check-on-face, and use only an inset `0 4px 8px -3px #0c0a1380` shadow. A 2px check-on-edge frame follows the card edge over the band, owner medallion and gold affiliation strip; the band is dimmed with `saturate(.85) brightness(.92)`. Hover tilt and moving sheen stay off; the press flattens a hover tilt over 420ms `cubic-bezier(.33, 1, .68, 1)` rather than the 220ms pointer-follow ease, so the card and its icons settle instead of jumping. An opened checked card retains its outer opened ring and glow; keyboard focus keeps its separate outline, and reduced motion makes the press immediate. Checked table rows use 22% check-on-face over card-face; adjacent rows merge with matching separators into one recessed block, with an inset `0 4px 5px -4px #0c0a1399` shadow only at the top and the normal separator at the bottom. The state strip and opened-row ring retain their meaning.

### Covers, counters and statuses

- Covers (2026-11-10) are a face lying on a frame. The face always carries the cover's color (below); the frame round it is clear glass (`--cover-glass`, white .62 → .4 in light, white .1 → .045 in dark), with no backdrop blur of its own, over a flat space panel. ## Elevation & Depth

- Menus and dialogs: --shadow 0 10px 28px #0c0a1366 (light theme: 0 8px 28px #30243812).
- Cards: card-shadow 0 2px 6px #0c0a1355; hover/focus: 0 6px 16px #0c0a1377. Covers share `--cover-rim` and `--cover-lift`; flat panels and the pulse bar share `--glass-rim` and `--glass-lift`; drag overlay uses `0 14px 28px rgb(0 0 0 / .45)` beneath the rim.
- Mint glow is limited to hover/focus and selected cards; unselected cards do not glow. There are no infinite decorative animations.

**The Depth Belongs to Cards Rule.** Card faces are matte. Sheen stays in the metallic bottom band; a mint ring and local glow indicate hover or an opened preview, while checked cards stay recessed. Unchecked cards tilt up to ±8deg for a softer motion (2026-11-09); deck covers do not tilt because tilt can look like displacement on the home screen. Dragging disables tilt and neighboring hover effects.

Use perspective 850px and requestAnimationFrame; disable tilt on touch and with reduced motion. Tokens: --motion-feedback 150ms, --motion-material 220ms, --ease-out cubic-bezier(.16, 1, .3, 1).

Metal reflection (2026-11-08): tile bands — the Hero footer, the Sub Card affiliation strip, Task and Doc footers — carry one rigid ribbon of metal under their ink (`.card-material-glare`, z-index -1, so numerals, icons and segments stay on top; its own `::after` repeats the band’s inset edge). Gold deepens with `--metal-amber`, other metal with `--metal-shadow`. At rest the hot cut sits beyond the right edge (`--glare-rest`), so the band reads as plain metal running dark to light with no reflection. The shared `useCardTilt` hook moves the cut through `--glare-shift`, in band widths at the tile’s mid-height: on enter it sweeps in once from the right, while hovered it follows the tilt — `0.377 − 0.522·(x − .5) + 0.485·(y − .5)`, against the pointer horizontally and with it vertically — and on leave it sweeps out to the right; every move is an exponential follow with a 77ms time constant. ### Controls

**The Foil Rule (2026-11-10).** Rounded hairline controls and lit glass panels can read as cheap capsules, and very dark surfaces can obscure the card preview's edge. The palette, page light, cards and covers stay; controls use smaller corners, one quiet line, a lighter label, and a chosen state marked by a line instead of a filled pill. Deckmate is an Operate tool, so its controls stay familiar and precise and give the depth to cards. Every interactive control is drawn one way, from `client/surface.css`:

- **Shape.** A 2px rectangle (`--control-radius`) for buttons, toggles, chips, segmented controls, rail buttons, fields and the closed part of selects. No capsules: round ends belong only to switch tracks, avatars, medallions and status dots. One deliberate exception: the server status badge in the top bar («Live», where every save shows) stays a capsule.
- **Edge.** A `.67px` hairline (`--control-hairline`, one device pixel at 150%) in `--control-line` — today's `--button-line` mixed 62% into the page ground, quiet at rest; hover brings the full `--button-line`.
- **Label.** Source Sans 3 500 with .01em tracking: 13px in a 30px tool, 12px in a 24px compact control, 14px in a 32px reading or dialog action; the primary action is 600; numbers inside are Geist Mono. No 700 on controls.
- **Sizes.** 24px compact (panel buttons, chips, inline toggles), 30px tools (toolbars, heads, fields, 30×30 icon buttons), 32×32 rail buttons and 32px reading and dialog actions.
- **Variants.** Outline (`.control`, `Button variant="outline"`): transparent, the quiet hairline, `--button-ink` — the secondary button and the off state of every toggle and chip. Ghost (`.control.control-ghost`, `variant="ghost"`): no visible edge, a muted icon — icon buttons in heads and footers. Primary (`variant="default"`): the violet fill (`--violet-fill`, `--violet-fill-ink`), 600 label, one per region. Creating (`.action-mint`): a mint hairline round a mint label on no face (`--action-mint-line`, `--action-mint-ink`; mint-ink on the light theme), for Journey and a screen's one creating action. Destructive (`.destructive` on an outline): danger ink and a danger hairline; a dialog confirms with the solid `--danger-fill`.
- **States.** Hover is a flat `--hover` fill, the ink color and the full `--button-line`, on pointers that hover only (`hover: hover`), so a tap leaves nothing behind. Chosen (`aria-pressed="true"`, `.is-on`, `aria-current="page"`: a toggle that is on, a chip that filters, the current scope, the rail button of the open panel) is **the mark**: a `--mark` hairline and a `--mark` label over `--mark-tint` (`--mark` is the accent #7443a6 in light and #d4b4ff in dark; the tint is the accent at 9% / 16%), never a filled pill; its hover deepens the tint (`--mark-tint-strong`). One exception: the open card's four workflow-state buttons (start ▷, open dependencies, review, accepted; `client/card-state-row.css`) show the current state by a solid fill of that state's colour — started or working, danger for open dependencies, review, accepted — because the fill replaces the written state label the row no longer carries. A pointer press moves the control 1px; disabled dims to .5 after the busy delay and ignores hover. Only flat colors change between states, so every state eases over 150ms and nothing blinks.
- **Fields** (`.control-field`: text inputs, search boxes, the closed part of a select): a recessed well (`--control-field`, ground in dark, surface in light) with a quiet hairline (`--control-field-line`); hover brings the violet hairline; focus turns the edge itself the focus color (1.67px) beside the caret, with no ring round the field.
- **Segmented** (`.control-segmented`): one quiet hairline frame, segments split by the same line, the chosen one carries the mark (its hairline drawn inside the segment).
- **Tabs** that switch a page section (`.control-tabs`, `.control-tab`; Hand): label only, 14/600 in every state (choosing never shifts the neighbours), muted until chosen, 38px tall, a 2px `--mark` underline on the chosen tab over a 1px rule. The top-bar tabs keep their trapezoids and fills.
- **Counters** keep their plates (Hand tab counts, cover counts) rather than hairline cells.
- **Glass is gone from chrome.** Panels are flat: `--glass-radius` 4px at every width, `--glass-face` one flat face (white .045 dark, .5 light), `--glass-rim` a crisp 1px edge (white .1 dark, plum 20% light), no lift in dark and a 1–2px shadow in light, `--glass-blur: none` (the token names stay from 2026-11-09). A narrow column of short sections is one `.glass-sheet` split by `--glass-seam` hairlines (`.glass-section`; a `.glass-panel` placed in a sheet becomes a section), not a stack of separate panels; nothing inside a panel is drawn as another box. Dialogs, popovers, menus and toasts share the same 4px corner.
- **Type in chrome.** Page titles 26/600 with -.015em; panel and dialog titles 15/600 and 18/600; readout labels and counts keep their case and colour. No bold 700 on controls or chrome titles.

**Focus.** One indicator, for the keyboard only: a 2px `--focus` outline 2px outside the edge (`:focus-visible` in `client/styles.css`). It never appears after a click or a tap: the browser keeps `:focus-visible` off for pointer focus, and focus moved by script goes through `moveFocus` (`client/focus.ts`), which passes the last input — key or pointer — as `FocusOptions.focusVisible` (Chrome 152 and WebView2 157 honor it). A control that marks focus its own way turns the ring off instead of adding a second frame: text fields and field boxes (their edge), menu and listbox rows (their highlight), card tiles (their own outline, single after Escape), the panel resize handle (its line). A pressed or selected control reached by keyboard keeps the ring: its mark says what is chosen, the ring says where the keyboard is.

## Do's and Don'ts

### Do:

- Do keep the dark theme as the default, using `:root.dark` tokens; add new colors as tokens, not hardcoded values.
- Do keep the light theme functional with tokens, not hardcoded colors.
- Do preserve Source Sans 3, Geist Mono, Roboto Mono, and the specified dimensions: 146.67×200 gallery cover, 165×225 shelf face and 132×180 settings preview, 115×147 card, resizable 420–800px sheet, 355 subcard panel, and 7 Hand slots.
- Do distinguish covers, Task, Hero, and Doc; calculate counters and progress from real data.
- Do preserve input during WS refresh and conflicts, keyboard focus, safe Markdown, and reduced motion.
- Do verify layout measurements (`npm run capture`) alongside reference images.

### Don't:

- Don't switch the default to the light theme or restore the old gallery dimensions (175×235, 165×225, 132×172) without an approved design change.
- Don't substitute visual review for technical checks or carry results from old builds over to new ones.
