# UI map

Code is the source of truth. Use this map to find the entry point, feature CSS, shared pieces and the narrowest useful checks before changing the interface. Routes below are relative to the running board; `catalogSource` is normally `sandbox` for the writable test copy or `live` for the original.

`client/main.tsx` loads the baseline `client/styles.css`, `client/surface.css`, `client/motion.css`, `client/select.css` and `client/card-material.css`; `client/App.tsx` adds `client/workspace.css`. The screen table lists feature CSS in addition to that baseline. [DESIGN.md](../DESIGN.md) explains the visual rules; this document locates their implementation.

## Themes, responsive layout and shell branches

- **Theme:** `ThemeToggle` selects light, dark or system. Both Vite builds emit the blocking `client/theme.js`, which reads the shell preference before browser-only storage and the system theme. Base `:root` is light and `:root.dark` is dark in the shared `client/tokens.css`; component rules live in `client/styles.css`, `client/surface.css` and `client/card-material.css`. The start screen imports the same tokens through `client/desktop/start.css`.
- **Input/motion:** `client/styles.css` owns keyboard-only focus and the global reduced-motion rule; hover-only rules use `(hover: hover)`. `tools/layout-capture.ts` starts desktop, fine-pointer, motion-allowed pages, so touch and reduced-motion checks must emulate those modes explicitly.

| Width / query | Current layout branch to check |
|---|---|
| ≤1180 / ≤1000 px | Compact server status and search geometry; open-deck tools wrap to another row; catalog Track selector moves rows; global results retain a 350 px column. |
| ≤980 / ≤900 / ≤860 px | Project pulse becomes two columns; Hand reduces padding; global tabs take their own row; Members rows change grid. |
| ≤760 px | Left panel and cards become one column, resize handle disappears, card reading/dock flows with page scroll; Vision, CSV, planning and deck panels have local narrow rules. Table uses a container query at 760 px to fold Tags. |
| ≤700 / ≤600 px | Catalog navigation stacks; some dialogs/pickers stack; Hand and open-deck secondary text compact further. |
| ≤480 / ≤420 px | Global search takes a full-width line and project menu fills the phone; page titles/mint actions compact; gallery uses its phone inset and centered two-cover rows; notifications and several forms have phone rules. |
| Container ≤460 px | Table rows become two-line blocks; card group controls move to another row. Open-card title actions have a separate 400 px container branch. |

**375 px review:** check horizontal overflow and every scroll owner; top-bar search/actions; two-cover gallery rows; filter and selection wrapping; Table’s two-line rows; card dock/band and family panel; CSV’s intentional table scroller; long project/member/tag names; notifications; Journey and template dialogs; Vision toolbar/sidebar. Repeat in dark/light, English/Russian, keyboard-only and reduced motion. Use `--width 375 --height 812 --dpr 1` with the capture command below.

## Capture and visual checks

Run captures against the current build. `npm run capture` needs a running board and Edge/Chrome (`DECKMATE_BROWSER` overrides discovery); it defaults to 1700×1000 at DPR 1.5 and writes a layout tree plus PNG.

```sh
npm run capture -- --url "http://127.0.0.1:4320/?view=deck&catalogSource=sandbox&scope=all&layout=table" --out .deckmate/captures/card-table --width 375 --height 812 --dpr 1 --color-scheme dark
```

This example writes `.deckmate/captures/card-table.json` and `.deckmate/captures/card-table.png`. Add `--step "click:<text>"`, `--step "wait:<ms>"`, `--step "eval:<script>"`, or `--clip <css-selector>` for another state; `--steps <file.json>` reads the same step list from a file. See `tools/layout-capture.ts` for hover, mouse and mid-drag steps.

| Command | Purpose and exact output |
|---|---|
| `npm run capture -- --url <url> --out <prefix>` | One arbitrary board state from the running app; `<prefix>.json` and `<prefix>.png`. This is the command to use for a single changed screen. |
| `npm run shots` | Run after `npm run build`. Builds a temporary writable demo and captures README images into `docs/screenshots/`, plus `docs/social-preview.png` and `docs/social-cards.png`; layout/evidence JSON goes into `.deckmate/shots/`. `npm run shots -- --social` captures only the social preview without the demo server. |
| `npm run capture:launcher` | Starts a private Vite server with `desktop.vite.config.ts`, drives the `client/desktop/` pages through the development-only mock bridge, checks keyboard flows, and writes all start/What’s new frames and `frames.json` into `.deckmate/launcher-shots/`. `DECKMATE_LAUNCHER_CAPTURE_OUTPUT` changes that directory. |
| `npm run capture:launcher -- --readme` | Single launcher frame at `docs/screenshots/desktop-start.png`; useful when only the README start image changed. |
| `npm run desktop:smoke` | Windows-only end-to-end check of the real debug WebView2 window, not a screenshot generator. First run `npm run build`, `npm run build:desktop` and `cargo build --manifest-path desktop/src-tauri/Cargo.toml`. It uses isolated temporary state, prints `ok <step>` lines and cleans up; native menu/dialog items still need the manual checks in `desktop/README.md`. |
