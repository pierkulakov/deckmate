## Board layout

- A deck groups one entity area (units, weapons, map objects, mechanics, tools); a unit deck contains only units, and Task decks group disciplines.
- For one game, prefer separate game-description and discipline-work spaces; keep process and technical references in an optional knowledge space.
- A Hero is what gets built; its work items are Sub Cards in discipline Task decks; the Hero links the work, not the deck.
- Game content (a tree, a fence) is not part of the tool that places it.
- How the game works belongs in a rule Doc beside the entity: an entity-only Doc may be its Hero's Sub Card, and rules shared by several Heroes prefer one top-level Doc linked from each; the Hero may summarize progress under Already works / Уже работает.
- Shared behavior is a mechanic with its rule; entity-specific behavior belongs to the entity's Hero.
- Keep one-off gameplay systems in a Systems deck; plan them without requiring a recurring asset pipeline.
- Create similar entities with a Journey step-chain template, not manual placement.
- Before creating a deck, check for a same-purpose deck with the same name in this project and space.
- During organization, do not create cards for completed work or accept work; preserve existing accepted work. Elsewhere never accept your own work — an independent reviewer follows the project's acceptance policy.
